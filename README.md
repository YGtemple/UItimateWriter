# UItimateWriter · 全品类中文写作 Skill

> 一句话简介：单入口、按需加载的全品类中文写作系统——三层去AI味 + 九大写作场景 + 文风复刻 + 自检脚本，把"怎么写好"从玄学变成可执行的工程。

## 一、项目概述与定位

**UItimateWriter**（注意开头是大写 U + 小写 I，不是 UI）是一个面向 AI Agent（Claude Code、Codex 等支持 `SKILL.md` 的智能体）的中文写作技能包。仓库根目录下有一个详尽的 `README.md`（约 37KB），真正的技能体位于子目录 `ultimate-writing/`。

它解决一个非常具体的问题：**AI 写出来的东西"通顺，但没人味"**——开头像模板、结尾像硬凑，读两行就知道是机器写的。项目的核心设计原则只有一句话：**先像人，再像文章。**

与市面上"一个更好的提示词"不同，它把"怎么写好"工程化：写作前有选题与标题方法论，写作中有场景规范与文风系统，写作后有分级自检、量化质量门和可运行的 AI 痕迹扫描脚本。理念是"不是感觉写得不错，而是检查通过才交付"。

项目融合了 30+ 个 GitHub 开源写作类项目的方法论（sub-README 的"致谢"章节列出了 humanizer、avoid-ai-writing、stop-slop、nuwa-skill、novel-writing 等十余上游项目），采用 **MIT 协议**开源。

### 三层去 AI 味体系（项目灵魂）

项目引用 2025–2026 年的 AI 写作检测研究指出：即使把 AI 文章所有禁用词换掉，仅靠话语结构特征仍能以 85%–93% 的准确率识别 AI 写作；最底层、最难伪装的是认知特征。因此分三层清理：

1. **表层**——删开头套路（"在当今……的时代"）、元话语（"值得注意的是"）、总结套路、空洞强调、互联网黑话、翻译腔、被动成瘾、"的的不休"；并处理"不是 A 而是 B"平行否定、三段式排比、破折号成瘾、反问自答等高频 AI 句式。
2. **话语层**——查 8 个习惯：结尾点题、单轨推进、人造闭环、情绪写成生理反应、氛围开头、无名泛指（"有研究表明"）、没有读者、批量趋同。
3. **认知层**——计算句子长度方差（burstiness：人类 0.6–1.2，AI 仅 0.2–0.4）、"我们"滥用 vs"我/你"缺席、情绪具体性缺失、hedge 悖论、段末重述主题句、段落间文体变化缺失。

## 三、技术栈与依赖

- **语言**：以 Markdown 规则文档为主（Skill 本体），辅以两个 Python 3 脚本；无第三方依赖，仅用标准库（`re`、`sys`、`statistics`、`argparse`）。
- **运行方式**：脚本直接 `python3` 运行；Skill 本体由支持 `SKILL.md` frontmatter 的 Agent（如 Claude Code、Codex）加载。
- **安装**：克隆到 `~/.claude/skills/ultimate-writing`（Claude Code）或 `~/.codex/skills/`（Codex）后重启 Agent 即可全局使用。

## 五、核心模块/关键文件解读

### 1. `SKILL.md`（主入口路由器）
带 YAML frontmatter（`name: ultimate-writing`，一段详尽的中文 `description` 列出覆盖场景与触发词，如"写文章、润色、改写、去AI味、仿写、写小说、写论文……"）。它定义了**八步工作流**：①识别需求 → ②加载内核（core 三件套，每次必做）→ ③按需加载一个 mode → ④可选叠加一个 style → ⑤改写任务加载 revise → ⑥查 templates/references → ⑦写作 → ⑧自检交付。文件末尾附完整文件索引与 10 条不可违反的写作铁律（禁编造、禁空话凑字、禁机械排比、禁元话语、禁空洞升华、禁翻译腔、禁 AI 自曝身份、保护作者声音、段落要短、写完读一遍）。

### 2. `core/core-humanize.md`（去 AI 味内核）
约 13.9KB，是所有写作任务的强制内核。除三层清理规则外，还专门列出"中文特有问题"（欧化长句、名词化、"是……的"强调句冗余、量词堆砌、程度副词成瘾、书面连接词、"我们"泛滥），以及"恢复人类纹理"的加法预算——可以加长短句交替、以"但/所以"开头、具体数字名字、作者真实判断、轻微不完美；**不能加**编造的人名数据、营销号语气（"家人们谁懂啊"）、无意义废话。

### 3. `core/core-rules.md`（写作铁律 38 条）
分七类：事实铁律、内容铁律、语言铁律、结构铁律、改写铁律、小说铁律、学术铁律。场景模块只能加规则不能减规则。例如"具体碾压抽象""展示不要告知""数据要翻译成人话""重要人物不能裸登场""学术写作不强行去 AI 味"。

### 4. `core/core-self-check.md`（分级自检体系）
P0（致命：编造事实、AI 自曝、逻辑断裂）/P1（结构混乱、套话密集）/P2/P3/P4 五级，每级配可勾选清单；P0/P1 不过不能交付。另附五维质量门（直接/节奏/可信/真诚/密度，各 1–10 分），并按公众号、报告、论文、文案、短视频、小说、改写给出不同自检侧重。

### 5. 九大 mode 场景模块（各 2.6–5.5KB）
每个模块独立定义字数、结构、写作要求与自检项，互不干扰：
- **公众号长文**：开头 800–1500 字切入，主体 7 种推进方式（现象/人物/利益/争议/数据/历史/比较）交替，每 1500–2500 字一个呼吸点。
- **议论文**：立场鲜明不和稀泥，事实/逻辑/反驳三种论证交替，反驳用反方最强论点（不打稻草人）。
- **报告/总结**：结论先行，数据说话，行动项必须有负责人和截止时间，删"在领导正确带领下"类空话。
- **科研论文**：IMRaD 结构，每事实有出处，方法精确到可复现，被动语态与 hedge 是规范而非 AI 味。
- **技术科普**：先讲人话再讲逻辑，术语首次出现给定义，类比标注边界，避免"知识的诅咒"。
- **营销/种草**：AIDA 结构，卖结果不卖功能，卖点不超过 3 个，有缺点才可信。
- **短视频脚本**：前 5 秒 Hook，口播友好，一句一意，每 5–8 秒一个信息点，附分镜表格模板。
- **网文小说**：黄金三章、3-5-10 节奏法则、项目文件管理（故事圣经/人物档案/时间线/伏笔台账）、续写协议。
- **经验贴**：真实第一、方法具体到"用什么、怎么做"、写踩坑、承认运气与局限。

### 6. 文风与改写模块
- **style-nuwa.md（女娲）**：从样本按词汇/句法/段落/修辞/声音 5 维提取风格画像，再按画像写作，并用"盲测法"验证保真度；强调只学"怎么写"不抄"写什么"。
- **style-literary/business/oral/academic.md**：四种预设文风，各给词汇、句式、段落、声音特征与 AI 腔对照示例。
- **revise-deai.md**：重度去 AI 的三遍稿工作流——**砍**（删套话，常缩短 30%–50%）→ **改**（抽象改具体、被动改主动、修复话语层）→ **养**（恢复长短句节奏与真实判断，但不编造）。
- **revise-logic.md**：诊断 10 类逻辑谬误（相关当因果、以偏概全、稻草人、虚假二分、循环论证、滑坡、论证跳跃、前后矛盾、证据不相关、偷换概念）。

### 7. 参考资料 references
- **ref-banned-words.md**：中文套话/黑话/翻译腔 + 英文 Tier1–3 banned words & phrases + 小说专项禁用 + 场景豁免表（学术/法律/技术文档例外）。
- **ref-novel-craft.md**：约 9.5KB 的小说工艺——场景最小结构（目标/冲突/结果）、人物展示四层次、对话潜台词、视角管理、伏笔台账、黄金三章、情绪值曲线（-9 到 +9）、反转四招、俄罗斯套娃式悬念、高潮六招。
- **ref-title-topic.md**：选题三问、四个价值锚点、爆款选题公式、六类标题公式与避雷。
- **ref-source-eval.md**：来源 S/A/B/C 分级、单条来源五问、关键事实双源交叉验证。
- **ref-voice-profiles.md**：直接/温和/权威/叙述/对话五人设的词汇、句式、声音与禁忌。
- **ref-wechat-html.md**：公众号全内联样式规范，11 类组件（章节卡片、金句卡、数据卡、时间线等），十套主题配色（竹青/科技蓝/暖橙/森林绿/典雅紫/中国红/墨黑/日落橘/青蓝/玫红），禁用 style 标签/class/JS/position/float。
- **ref-before-after.md**：去 AI 味、润色、节奏的前后对照案例。

### 8. 两个 Python 脚本
- **`scripts/word_count.py`**：统计口径与 Word/WPS 一致（中文字符 + 英文单词 + 数字串），先剥离 HTML 标签/注释/script/style 块并反转义实体，支持 `--min/--max` 自动判定字数是否达标。
  用法：`python3 scripts/word_count.py article.md --min 2000 --max 5000`
- **`scripts/scan_ai.py`**（约 12KB）：AI 痕迹扫描器，扫描四类问题——①严重（AI 身份声明、拒答话术、客服式结尾，命中即不合格，退出码 1）；②警告（模板化套话/黑话/句式模式）；③占位符（TODO、example.com 等）；④结构层认知特征：计算 **burstiness**（句子长度变异系数 CV，≥0.55 自然 / 0.35–0.55 偏均匀 / <0.35 机器节奏）、代词分布（"我们"密度/千字）、hedge 密度。这是把"机器节奏"量化识别的核心工具。

## 六、运行与使用方式

Skill 本体无需"运行"，由 Agent 加载；两个脚本可独立命令行执行：

```bash
# 字数统计（含上下限判定）
python3 scripts/word_count.py article.md --min 2000 --max 5000

# AI 痕迹扫描（结构层 + 套话 + 身份声明）
python3 scripts/scan_ai.py article.md
```

日常使用直接用自然语言向 Agent 下达写作需求，Agent 会按 `SKILL.md` 的路由表自动识别场景、加载对应模块。例如："帮我写一篇关于 AI 取代客服的公众号文章，3000 字，口语化风格""把这段文字去 AI 味""用文艺文风写一篇关于老城区拆迁的散文""模仿我之前文章的风格写一篇新的"。

## 七、数据/资源构成

仓库全部为**文本/规则资源**，无图片、音视频、字体、压缩包等二进制文件。共 40 个文本文件（1 个根 README + 3 个技能根文件 + core 3 + mode 9 + references 7 + revise 5 + scripts 2 + style 5 + templates 5）。技能通过"主入口薄、模块按需加载"的方式控制上下文占用。

## 八、适用场景与项目特点

- **目标用户**：自媒体/内容创作者、网文小说作者、职场人（报告/总结/邮件）、学生/研究者（论文/综述/经验贴）。
- **项目特点**：
  1. **工程化写作**——把主观"感觉"变成可机械执行的清单、分数和脚本。
  2. **三层去 AI 味**——不只换词，连话语结构与认知特征一起改，这是与普通"去 AI 味"提示词的本质区别。
  3. **减法优先、事实零容忍**——80% 的 AI 味靠删解决，宁可短不可假，不编造人名数据来"假装是人"。
  4. **保护作者声音**——改写保留原文细节、对话与独特比喻，不把活的文字压成光滑摘要；明确反对"从 AI 腔改成营销号腔"。
  5. **上下文友好**——单入口 + 按需加载，避免规则互相冲突。
