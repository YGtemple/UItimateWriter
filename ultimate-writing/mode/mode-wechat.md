# 公众号长文模式

## 定位

微信公众号深度原创长文。读者在手机上读，会被消息打断，随时可能退出。每一段都要给读者一个继续往下滑的理由。

## 字数

- 用户指定字数时按用户要求。
- 未指定时：深度长文 5000-15000 字；常规干货文 2000-5000 字。
- 字数用 `scripts/word_count.py` 实测，不估算。

## 选题与标题

动笔前先卡选题，再想标题。完整的选题公式和标题公式见 `references/ref-title-topic.md`，这里只给核心：

- **选题先过三问**：用户关心吗？有新意吗？有落点吗？三个有一个答不上来就换。
- **选题踩一个价值锚点**：情绪价值 / 实用价值 / 认知价值 / 社交价值。
- **标题 3 秒定点击**：数字+利益、反差悬念、痛点提问、标签人群、民生共情，选一个，别套模板。
- **标题避雷**：太文艺、太抽象、太官方、违规夸大、标题党。

## 结构

### 开头（800-1500字）
用以下任一方式切入，禁止"随着……的发展"开头：
- 一个具体场景：时间、地点、人物、动作
- 一个人物故事：某人遇到了什么
- 一个反差事实/数据："XX涨了300%，但没人知道为什么"
- 一句对话：直接引语开场
- 一个反常识判断："你以为的XX，其实是YY"

三段内亮出核心问题或核心判断。

### 主体
7种推进方式交替使用，不要只用一种：
1. **现象层**：发生了什么，具体描述
2. **人物层**：谁在经历，他们怎么说
3. **利益层**：谁赚钱、谁亏钱、钱怎么流
4. **争议层**：不同立场怎么吵，各自的道理
5. **数据层**：数字揭示了什么趋势
6. **历史层**：以前是什么样，怎么变成现在这样
7. **比较层**：不同地区/公司/人群的差异

每 1500-2500 字插入一个"呼吸点"：小故事、引语、反问、数据卡片、场景描写。

### 结尾（800-1500字）
- 回到开头的人物或场景，形成闭环
- 给出你的判断和态度
- 可以留一个开放问题
- 不喊口号，不空洞升华

## 写作要求

1. **第一人称"我"在场。** "我翻了几百条评论后发现"比"据统计"好。
2. **每章至少1-2处带引号直接引语。** 来自真实素材，不编造。
3. **图注是正文延伸。** 好图注："这家开在巷子里的小店，菜单已经换了三回。" 差图注："图为某店铺照片。"
4. **参考资料放文末。** 正文不放URL，文末统一列出来源名称和链接。
5. **数据要翻译。** "同比增长23.7%"→"去年卖100块，今年卖124块"。
6. **每章结尾留钩子。** 引向下一章的问题、悬念或转折。

## 排版规范

- Markdown 格式交付。
- 一级标题用 `##`，二级用 `###`。
- 重点句可以加粗，但不滥用。
- 引用用 `>`。
- 数据/对比可以用表格。
- 用户需要 HTML 排版时，按 `references/ref-wechat-html.md`：所有样式内联（style="..."），不用 class/id/外链CSS/JS；用组件打破长文节奏；配色 ≤3 种。

## 多平台调研（非虚构长文）

写非虚构长文时，素材来源应覆盖多个平台，事实核查走 `references/ref-source-eval.md`：

- 搜索引擎：新闻、报道、官方信息
- 视频平台：提取字幕和评论（如有工具支持）
- 社交平台：微博、知乎、小红书等观点和亲历者叙述
- 每条素材记录：平台 | 时间 | 核心事实/观点 | 原文金句或数据 | 来源
- 关键事实至少两个独立来源交叉验证
- 来源分级：一手来源 > 权威二手 > 普通二手 > 自媒体；自媒体只作线索不作事实依据

## 自检额外项

- [ ] 开头三段内有没有亮核心？
- [ ] 每章有没有至少一个具体人物或具体故事？
- [ ] 有没有连续超过2000字没有呼吸点？
- [ ] 数据有没有翻译成人话？
- [ ] 文末有没有参考资料？
- [ ] 图注是不是正文延伸而非图片说明？
